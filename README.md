# NAVI CS2 dashboard

Мобільний дашборд уболівальника: сезон NAVI CS2 з 1 січня 2026, пояснена смуга шансу і пульс публічних дописів. Окремого логіна немає.

Інтерфейс українською. Час матчів — `Europe/Berlin`. Палітра: теплий фон, чорний, жовтий NAVI.

## Звідки дані

- Серії, карти і склад читаються з публічного MediaWiki API Liquipedia. Модуль `action=cargoquery` на вікі зараз не відкритий, тож синк іде через той самий API в LiquipediaDB (`mw.ext.LiquipediaDB`), з описовим User-Agent і паузою щонайменше 2 секунди між запитами. На сайті є підпис «Дані: Liquipedia».
- HLTV не використовується. Rating 2.0, ADR і KAST не вигадуються. K/D з’являється лише якщо джерело віддало і кіли, і смерті.
- Пульс: новини CS2 з публічного JSON navi.gg і публічні Telegram-канали, на які посилається Liquipedia (клуб і гравці). X і Instagram пропускаються.
- Тон допису — словник: спокійно / зібрано / напружено. Це тон тексту, не висновок про людину.

## Шанс серії

Перед майбутньою серією синк зберігає смугу:

- 50% база
- форма NAVI і суперника за останні 10 серій
- особисті зустрічі у 2026
- край по картах, якщо в джерелі є результати карт

Діапазон стискається приблизно до 15–85% і показується як «близько 58–64%» плюс до трьох причин. На картці є рядок, що це оцінка за відкритою статистикою і не порада для ставок. Після матчу замість смуги — рахунок.

## Локально

Потрібні Node.js 22 і Postgres.

```bash
cp .env.example .env
# У .env вже є приклад локального DATABASE_URL і CRON_SECRET.
npm install
npm test
npm run sync
npm run dev
```

Локальна база з цього середовища:

```bash
# користувач navi / база navi, пароль у .env.example
npm run sync
npm run dev
```

Сторінки: `/`, `/matches`, `/matches/[id]`, `/players`, `/players/[id]`, `/pulse`.

Кнопка «Оновити» викликає той самий `runSync`, що й cron. Секрет у браузер не потрапляє.

Ручний виклик ендпоінта:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" http://127.0.0.1:3000/api/sync
```

## Деплой

`vercel.json` ставить cron раз на добу (`0 5 * * *`, 05:00 UTC) на `/api/sync`. На Vercel задай `DATABASE_URL` (Neon або інший Postgres) і `CRON_SECRET`. Vercel надсилає `Authorization: Bearer <CRON_SECRET>`.

Повний синк робить кілька запитів із паузою, тож йому потрібно більше за 10 секунд. Hobby-ліміт функції може обірвати cron; локально і на плані з `maxDuration` 60 синк встигає. Перший сезон можна залити командою `npm run sync`, якщо платформа обрізає HTTP-виклик.
